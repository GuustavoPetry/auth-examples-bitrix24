Guia de autenticação com o Bitrix24

Passo a passo das duas formas de autenticar com o Bitrix24 usadas neste projeto: do cadastro do app no portal até o recebimento dos tokens.

1. Contexto automático app dentro do Bitrix24

Usado quando o app roda dentro do portal (num iframe). O próprio Bitrix24 injeta os tokens a cada carregamento — sem tela de login, sem redirecionamento.

Bitrix24 (portal)
— POST automático →
Seu servidor /install
→
Tokens exibidos

  1. Crie o app local no Bitrix24

    No seu portal, vá em Desenvolvedores → Outro → Adicionar aplicativo local.

  2. Configure a URL de instalação (handler)

    Informe a URL pública do seu servidor seguida de /install, por exemplo: 

    https://sua-url-publica.com/install

    Se estiver testando local, exponha a porta 3000 com um túnel (ex.: ngrok http 3000).

  3. Salve e instale o app

    Ao instalar, o Bitrix24 já faz o primeiro POST /install sozinho.

  4. Abra o app dentro do portal

    A cada abertura, o Bitrix24 repete o POST para o handler, enviando no corpo campos como AUTH_ID (access token), REFRESH_ID (refresh token), member_id, DOMAIN, entre outros.

  5. Pronto — tokens na tela

    A rota POST /install deste projeto loga tudo no console e devolve uma página HTML mostrando exatamente o que o Bitrix24 enviou.

Simulando localmente sem precisar do Bitrix24:

curl -X POST http://localhost:3000/install \
  -d "AUTH_ID=token_fake" \
  -d "REFRESH_ID=refresh_fake" \
  -d "DOMAIN=empresa.bitrix24.com.br" \
  -d "member_id=abc123"

2. OAuth2 completo app fora do Bitrix24

Usado quando o app é acessado fora do portal. Segue o protocolo OAuth2 "Authorization Code": o usuário autoriza numa tela do Bitrix24 e o app troca um código por tokens.

Navegador
→
Bitrix24 (autoriza)
— redirect c/ code →
Seu servidor /oauth/callback
— troca code →
Bitrix24 (token)
→
Tokens exibidos

  1. Cadastre o app e anote as credenciais

    Em Desenvolvedores → Outro → Adicionar aplicativo local, anote o client_id e o client_secret gerados.

  2. Defina o redirect_uri

    No cadastro do app, aponte a URL de redirecionamento para:

    https://sua-url-publica.com/oauth/callback

  3. Configure o .env

    BITRIX_CLIENT_ID=<client_id do app>
BITRIX_CLIENT_SECRET=<client_secret do app>
BITRIX_PORTAL_DOMAIN=empresa.bitrix24.com.br
BITRIX_REDIRECT_URI=https://sua-url-publica.com/oauth/callback

  4. Suba o servidor e abra a URL de autorização

    Com npm start rodando, abra no navegador GET /oauth/authorize — essa rota só monta a URL de autorização do Bitrix24 com seus dados e redireciona você para lá.

  5. Faça login e autorize o app

    Na tela do Bitrix24, entre com sua conta e clique em autorizar.

  6. Bitrix24 redireciona de volta com um "code"

    O navegador é redirecionado (sempre via GET) para o seu redirect_uri, com code e domain na URL.

  7. Servidor troca o code por tokens

    A rota GET /oauth/callback chama o endpoint oficial do Bitrix24 (oauth.bitrix.info/oauth/token/) trocando o code por access_token e refresh_token reais.

  8. Pronto — tokens na tela

    A página final mostra tudo que o Bitrix24 devolveu, e o console do servidor também loga a resposta.

Testando manualmente com um code já obtido (sem passar pelo navegador):

curl -X POST http://localhost:3000/oauth/callback \
  -d "code=CODE_RECEBIDO_DO_BITRIX24" \
  -d "domain=empresa.bitrix24.com.br"

Referência das rotas

RotaQuando é chamada
POST /installAutomaticamente pelo Bitrix24, a cada abertura do app dentro do portal.
POST /oauth/callbackManual (curl/Postman), pra testar a troca de code por tokens sem navegador.
GET /oauth/callbackAutomaticamente pelo Bitrix24, redirecionando o navegador após a autorização (redirect_uri).
GET /oauth/authorizeManual, aberta por você no navegador para iniciar o fluxo OAuth2.

Dicas e problemas comuns

O Bitrix24 exige https pública para o handler e o redirect_uri — localhost sozinho não funciona. Use um túnel (ngrok, VS Code port forwarding, etc.) para testar local.
BITRIX_PORTAL_DOMAIN deve ser só o domínio (ex.: empresa.bitrix24.com.br), sem https:// na frente — o código já adiciona isso sozinho.
Nem todo carregamento do app envia os mesmos campos no POST /install — isso varia pelo tipo de placement (página cheia, slider, widget). A rota mostra dinamicamente tudo que veio, sem esconder nada.
